# Flash 图片与字库资源生成规范

> 触发条件：涉及 W25Q16、SPI Flash、外部资源 Flash、图片资源、字库、点阵、RGB565、Image2LCD、资源 `bin`、资源 `manifest`、Flash 分区、烧录地址或完整 Flash 镜像生成时，必须先阅读本文件。

本文件约束图片、字库和其他外部资源生成 Flash 固件的工作方法。资源固件不是普通二进制拼接，必须同时保持输入源、资源格式、Flash 地址、固件读取代码和交付说明一致。若同时涉及交付包、生产包或烧录文件交付，还必须继续阅读 `rules/specs/delivery_spec.md`。

## 生成前必须确认

- 先确认当前工程是否真的从外部 Flash 读取图片或字库，不能只因为存在 W25Q16 驱动、SPI 读函数或历史资源文件，就判断当前显示路径已经走外部 Flash。
- 必须追踪真实调用链：初始化入口、Flash 在线检测、资源读取接口、图片/字库查找接口、显示绘制接口、主循环或调度推进函数。
- 必须确认 Flash 型号、容量、页大小、扇区大小、地址宽度、读写能力和实际烧录方式，例如 W25Q16 常见容量是 `0x200000` 字节，但不能跨项目硬套。
- 必须确认资源输入源：图片源文件、导出的 C 数组、Image2LCD 输出、字库文本、点阵表、字体工具输出或已有 `bin`。
- 必须确认屏幕尺寸、像素格式、RGB565 字节序、坐标方向、透明/蒙版规则、帧数和每帧尺寸。
- 必须确认固件侧使用运行时解析资源表，还是使用生成头文件里的静态 offset/length 宏；两种方式的同步要求不同。
- 无法从源码、工程文件、README、manifest、原理图说明或已有工具脚本确认的硬件与资源信息，必须询问用户。

## Flash 分区与地址规划

- 生成资源前必须先写出 Flash 分区表，至少包含 Flash 总容量、每个资源包基地址、保留区、对齐规则、最后资源结束地址和推荐烧录地址。
- 图片、字库、音频、配置、日志等不同区域不得重叠；新增资源必须检查 `base + length` 是否越界和是否压到下一个分区。
- 分区地址使用绝对 Flash 地址表达，长度使用字节单位表达；不要混用 MCU 片内地址、资源内相对偏移和烧录器偏移。
- 包头、资源表、payload 起始地址、每项大小和填充值必须固定记录；烧录器填充镜像默认使用 `0xFF`，除非当前项目已有明确约定。
- 资源包需要按 Flash 页、扇区或烧录器要求对齐时，必须说明实际长度和填充后长度，不能只给一个无法追溯的 `bin`。
- 生成完整 Flash 镜像时，必须确认每个分区写入的偏移和 magic；例如图片包在 `0x000000`、字库包在 `0x010000` 时，要验证两个偏移处的 magic 都正确。

## 图片资源生成规则

- 每张图片资源必须记录名称、用途、宽度、高度、帧数、像素格式、字节序、Flash offset、长度和 CRC32。
- RGB565 原始数据长度必须满足 `width * height * frame_count * 2`；不满足时必须先判断是否带文件头、调色板、压缩头或工具私有头，不能直接烧录。
- 若图片来自 C 数组或旧工程资源头文件，必须保留数组名到资源 ID 的映射，并确认数组原始字节序与当前 LCD 写屏接口匹配。
- 多帧图片必须明确帧顺序和单帧长度；固件按帧索引读取时，必须检查 `frame_index * frame_len` 不溢出且不越界。
- 生成图片包时必须输出机器可读 manifest，推荐 JSON；需要人工核对或生产对照时同时输出 CSV。
- 生成固件头文件时，宏名、offset、length、width、height、frame count 和 entry count 必须全部来自同一份 manifest。
- 如果固件不运行时解析包头，而是用静态头文件访问资源，更新图片包后必须同步更新头文件和资源枚举，否则禁止交付。

## 字库资源生成规则

- 字库输入源必须记录编码方式，例如 UTF-8、GBK/CP936 或工具私有编码；解析中文点阵时不能默认 UTF-8。
- 每个字形必须记录字符、Unicode codepoint、宽度、高度、bytes_per_row、bitmap offset、bitmap length 和来源索引。
- 点阵长度必须满足 `bytes_per_row * height`；`bytes_per_row` 必须按当前点阵取模规则计算，例如 `(width + 7) / 8`。
- 字库索引表排序规则必须与固件查找算法一致；如果固件使用二分查找，生成工具必须按 codepoint 排序。
- 字库包必须有 magic、version、header size、entry size、table offset、data offset、data length 和 CRC32 等基本字段。
- 固件侧不能为节省检查而假设字库永远存在；初始化时应校验 magic/header，查找失败时应返回错误或降级显示。
- 空格、缺字、非法 codepoint 和超过最大点阵长度的字形必须有明确处理策略。

## 固件同步要求

- 资源包生成不是单独动作；必须同步检查固件里的 Flash 容量宏、资源基地址宏、资源枚举、资源表长度、读取接口和显示绘制接口。
- 固件应在编译期或初始化期检查关键不变量，例如资源包基地址、资源数量、最大地址、单帧长度和 Flash 容量。
- 外部 Flash 读取接口必须检查空指针、地址越界、长度越界、地址加法溢出、Flash 离线和底层硬件错误。
- 大图或整屏资源写屏必须走可调度的分块状态机；不要在业务层写长时间阻塞的 Flash 到 LCD 循环。
- 中断回调中不得直接解析资源、读取大量 Flash 或刷屏；只记录事件，资源处理放到主循环任务或调度任务。
- 若资源更新影响 UI 布局、显示刷新或长文本显示，还必须阅读 `rules/specs/oled_ui_spec.md`。
- 若资源更新需要修改 C 代码、驱动接口、超时或调度，还必须阅读 `rules/specs/coding_style_spec.md`。

## 输出文件要求

资源生成完成后，按项目需要输出以下文件：

- 实际长度资源包，例如 `*_pack.bin`。
- 烧录器友好填充包，例如 `*_pack_64k.bin` 或按扇区对齐的包。
- 纯 payload 包，仅在固件或工具明确需要时输出，并标明不含包头和资源表。
- 完整 Flash 镜像，例如完整 2MB 镜像，适合整片烧录或生产复制。
- manifest JSON/CSV，记录每个资源的尺寸、帧数、offset、length、CRC32 和用途。
- 固件头文件或等价定义，记录固件读取外部 Flash 所需的 magic、版本、基地址、资源数量和资源宏。
- README 或烧录说明，写清推荐烧录文件、烧录地址、包格式、分区布局和注意事项。
- SHA256 或其他项目指定校验文件，保证用户拿到的资源包可追溯。

## 校验要求

- 校验资源包开头 magic 是否与固件检查值一致。
- 校验 manifest 中每个资源的 offset、length、width、height、frame count 与固件头文件一致。
- 校验每个资源 payload 的 CRC32 与 manifest 一致。
- 校验实际长度包和填充包前缀完全一致，填充区域符合说明。
- 校验完整 Flash 镜像中每个分区基地址处的 magic 和包长度。
- 校验最后一个资源结束地址小于 Flash 容量，并且不会覆盖字库、配置、日志或其他分区。
- 资源固件配套 MCU 固件时，必须用当前工程真实构建方式重新构建，并确认资源头文件参与了本次构建。
- 没有上板验证时，必须在说明中写清“仅完成离线生成/一致性校验，未完成实机显示验证”。

## 禁止事项

- 禁止凭经验指定图片尺寸、Flash 地址、字节序或字库编码。
- 禁止把某个项目的资源名、地址、屏幕尺寸或字体格式写成跨项目固定规则。
- 禁止只交付一个裸 `bin`，不交付 manifest、烧录地址、格式说明和校验信息。
- 禁止资源包已经更新但固件头文件、枚举、manifest 或 README 仍沿用旧版本。
- 禁止把调试字库、调试图片或临时诊断资源混入正式资源包，除非文件名和说明明确标注为调试用途。
- 禁止因为工具能导出 RGB565，就跳过长度、字节序、CRC 和固件调用链校验。
- 禁止把外部 Flash 离线、资源缺失或 magic 错误伪装成正常显示结果。

## 完成检查清单

- 是否确认当前工程真实使用外部 Flash 资源，而不是只存在历史驱动或示例代码。
- 是否写明 Flash 分区表、基地址、容量、对齐和最后资源结束地址。
- 是否确认图片资源长度满足 `width * height * frame_count * 2`。
- 是否确认字库编码、codepoint 映射、点阵长度和索引排序规则。
- 是否生成并保留实际包、填充包、manifest、固件头文件、README 和校验文件。
- 是否检查资源包、manifest、固件头文件和固件枚举完全一致。
- 是否验证 magic、CRC、SHA256、填充区域和完整镜像关键偏移。
- 是否在需要时同步阅读并执行 `delivery_spec.md` 的交付包要求。
